1. Aldri kod direkte i main
 - Det skal aldri committes eller pushes direkte til main (eller master).
 - All utvikling skjer på en egen branch, opprettet fra siste versjon av main.
 - Bruk et konsistent navnemønster for branches, f.eks. feature/kort-beskrivelse, fix/kort-beskrivelse.
2. Les og forstå før du koder
 - Før noen endring gjøres, skal agenten sette seg inn i relevant kode, konvensjoner og dokumentasjon i repoet.
 - Se etter eksisterende mønstre (kodestil, mappestruktur, testoppsett) og følg dem, fremfor å innføre nye.
 - Ved usikkerhet om krav eller løsning: still spørsmål eller undersøk videre før implementering starter.
3. Pull request før noe merges
 - All kode skal inn via en pull request (PR) — ingen unntak.
 - Agenten skal aldri merge sin egen PR. Merge skjer først etter gjennomgang og godkjenning fra et menneske.
 - PR-beskrivelsen skal forklare hva som er endret og hvorfor, ikke bare liste filer.
